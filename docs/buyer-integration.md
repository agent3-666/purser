# Unpaid buyer preflight

`fetchUnpaidQuote` performs only the initial HTTP request. It refuses redirects, non-402 responses, absent x402 v2 `PAYMENT-REQUIRED` headers, a mismatched `resource.url`, and any caller-supplied payment or credential header. Only public `accept`, `content-type`, and `user-agent` request headers may be persisted. Use a pre-agreed GET or harmless POST body. This is a Purser policy for binding a quote to the requested resource; a rejected mismatch alone does not establish that the seller violates x402.

`verifyObservedQuote` calls the payee verifier for each parsed offer, independently fetching `https://<seller domain>/.well-known/x402-payee.json`. Use a persistent `PayeeLedger` when moving beyond a probe so rotation and nonce history survive restarts. A missing seller authorization is `unconfirmed`, never `confirmed`. Re-check immediately before any payment; the observed quote is time-sensitive.

The current `src/purchasing` experiment accepts only `local_native_transfer` offers. A real x402 HTTP offer must be marked `paymentRoute: "x402_http"`, which produces `payment_route_unsupported` in that executor. Sending a native transfer to the quoted `payTo` does not buy the resource.

`src/x402/gateway-buyer.ts` is a separate, opt-in single-attempt adapter for a pre-approved Arc testnet Gateway order. It re-parses the exact approved 402 header, fetches a fresh matching 402 before signing, binds the HTTP method, URL, body and public headers to the order, requires a **confirmed** seller-domain payee authorization at the real current time, checks chain/USDC/Gateway contract, per-order, daily and lifetime caps, and writes an ignored 0600 local journal before signing. It requires a persistent payee ledger and records the seller's authorization before signing. A later order with the same request hash is rejected. Circle's `BatchEvmScheme` creates the EIP-712 Gateway authorization; the adapter sends the matching x402 v2 `Payment-Signature` exactly once, without deposit, redirect or automatic re-sign/retry. The Circle SDK gives this authorization an approximately seven-day validity window; unknown outcomes remain reserved and need manual reconciliation. The EIP-712 signature itself binds transfer fields, **not the HTTP request body**; the journal only constrains this buyer's sends and cannot guarantee that a seller will not reuse the authorization during its validity window. Keep the journal on private storage. Its rename-based writes cover process crashes, not a guaranteed power-loss recovery contract.

A successful HTTP response with a `PAYMENT-RESPONSE` is recorded as `server_ack_unverified`, **not independent Arc settlement**. The local experiment checks Circle's server-side batching discriminator and cryptographically recovers the EIP-712 signer from the received wire payload. It does not call Circle's live facilitator, prove deposited Gateway balance, or observe an Arc transaction. The official server SDK's `BatchFacilitatorClient.verify/settle` calls Circle's Gateway service; that real verification remains a live integration gate. Do not use this adapter on production funds. No testnet payment has occurred.

For review, run `npx tsx research/probe_live_2026-09-29.ts` from the repository root. It captures the exact public 402 headers and body text in `research/live_quotes_2026-09-29.json` without payment. Do not interpret a 402 challenge as delivered value or external adoption. The prospective acceptance rules for the two internal tasks are in `eval/criteria.v1.json`; both remain blocked on unconfirmed payee authorization and live Gateway settlement, and GuardAgent also fails the current strict URL-binding policy.
